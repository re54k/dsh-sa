# 第 3 步：集成数据与交互逻辑

## 目标

把第 2 步生成的 Store/接口数据接到第 1 步的组件里（替换占位数据），并根据交互稿实现目标页面的交互功能（点击、跳转、弹窗、刷新、加载更多等）。

## 输入与输出

- **输入**：交互稿（目标页面部分）+ 第 1 步的组件 + 第 2 步的 Store/接口/类型
- **输出**：数据绑定完成、交互逻辑可用的页面

## 编排的子技能

| 子技能            | 在本步的职责                                         |
| ----------------- | ---------------------------------------------------- |
| `mf2e-falcon-rn`  | Store 用法、自定义 Hooks、导航/弹窗、事件通信        |
| `mf2e-rn-library` | 列表、下拉刷新、动画等三方功能库的正确 import 与用法 |
| `mf2e-mnb-api`    | 涉及原生能力（分享、跳转客户端页面等）时             |

## 执行流程

### 3.1 获取并筛选目标页面交互说明

1. **读取交互稿**（读取方式按第 0 步 0.1 的地址类型选择）
2. **按目标页面锚点筛选**（锚点来自第 0 步）：交互稿通常覆盖整个项目，只取目标页面的交互说明——页面内点击/滑动行为、页面间跳转、弹窗、状态切换等
3. **列交互清单**，向用户确认边界：

   ```
   📋 目标页面「<页面名>」交互清单
   1. 点击榜单条目 → 跳转到详情页
   2. 点击「公开/匿名」按钮 → 弹出确认弹窗 → 调 toggle-public 接口
   3. 列表下滑到底 → 加载更多
   ```

### 3.2 集成接口数据请求（绑定 Store）

把第 1 步的静态占位数据，替换成第 2 步 Store 的真实（mock）数据：

1. 读 `mf2e-falcon-rn` 的 `store.md` 和 `hooks.md`，按项目惯例使用 Store（如 `useRankStore`）
2. 在组件里按需触发数据请求：
   - 页面进入即加载 → `useEffect` 里调 `fetchXxx`，或用 `BaseSuspense` 管理加载态
   - 列表分页 → `useLoadMore` 或 Store 的 `fetchList` / `fetchMore`
3. 用 Store 返回的 `data` 渲染，字段按第 2 步生成的类型（`RankData` / `RankItem`）取用
4. **保持第 1 步的视觉还原不变**：数据接入是替换内容，不是重写布局样式

### 3.3 开发交互逻辑

按 3.1 的交互清单逐项实现。**实现前先读 `mf2e-falcon-rn` 对应规范**：

- 页面跳转 → `navigation.md`（`openPage` / 路由注册）
- 弹窗 → `navigation.md` 的弹窗章节 + `components.md` 的 `BaseDialog`
- Toast 提示 → `navigation.md` 的 Toast 系统
- 下拉刷新/加载更多 → `hooks.md` 的 `useLoadMore`
- 事件通信 → `navigation.md` 的 MNB 事件总线
- 分享 / 跳转客户端能力 → 加载 `mf2e-mnb-api`
- 动画 / 手势 / 列表等三方库 → 加载 `mf2e-rn-library`（确认包名、版本、import 路径后再用）

交互实现速查：

| 交互                | 项目对应能力                                                |
| ------------------- | ----------------------------------------------------------- |
| 页面跳转            | `openPage` / `navigator.open`                               |
| 弹窗                | `openDialog` + `BaseDialog` 变体                            |
| 轻提示              | Toast 系统                                                  |
| 下拉刷新 / 加载更多 | `useLoadMore`                                               |
| 分享                | `@/utils/share`                                             |
| 点击反馈            | `Pressable`                                                 |
| 列表 / 瀑布流       | `FlashList`（`mf2e-rn-library`）                            |
| 动画                | `Animated` / `react-native-reanimated`（`mf2e-rn-library`） |

> 具体 API 签名、import 路径以 `mf2e-falcon-rn` / `mf2e-rn-library` 技能内容为准，不要凭记忆写。

### 3.4 自测

1. 跑类型检查确认无类型错误
2. 在模拟器上走一遍交互清单：每个交互是否按交互稿触发、数据是否正确渲染
3. 发现交互/数据问题立即修正；涉及视觉的问题回到第 1 步的截图校验流程

### 3.5 本步出口条件

满足以下全部条件后，输出第 3 步验收摘要并**停等用户确认**，用户确认后才进入第 4 / 5 步：

- [ ] 3.1 交互清单逐项实现（未实现项标注原因）
- [ ] 类型检查通过；模拟器按交互清单走查通过
- [ ] 数据绑定未破坏第 1 步视觉还原（有偏差则回到第 1 步修正）
- [ ] 验收摘要已输出：已实现交互点、自测结论、遗留交互

**前置：第 2 步验收通过后本步才可开工；未获得用户确认，禁止开始第 4 / 5 步。**

## 常见陷阱

- **数据取错层级**：项目 fetch 封装可能返回解包后的 data 本体，也可能返回完整 `{code,message,data}`——以第 2 步探测的 fetch 语义为准，取错层级运行时必崩。
- **重复造轮子**：交互能力（弹窗/刷新/分享）项目多半已有封装，先查 `mf2e-falcon-rn` / `mf2e-rn-library` 再用，不要自己重写。
- **未确认库就 import**：三方库必须先确认 `package.json` 已安装，否则白屏。
- **改了逻辑丢了视觉**：数据绑定和交互开发以"不破坏第 1 步视觉还原"为前提。
- **忽略交互稿边界**：只实现目标页面的交互，别的页面的交互说明不要做进来。

## 与后续步骤的衔接

- 记录**已实现的交互点**（按钮、列表项、弹窗等），第 4 步要在这些交互点上挂埋点
- 若本步因交互稿缺失而跳过，页面只有数据绑定、没有交互逻辑——在报告中标注
